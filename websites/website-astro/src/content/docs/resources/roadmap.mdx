## Phase 2: Driver and Tooling Integration

Phase 2 focuses on making BCP accessible to tool and agent developers through integrations and language bindings.

| Deliverable | Status | Details |
|-------------|--------|---------|
| Driver with XML/Markdown/Minimal output modes | Done | Completed early during Phase 1. Three render modes with model-family-aware formatting. |
| CLI tool for inspecting, validating, converting BCP files | Done | Completed early during Phase 1. Commands: `inspect`, `validate`, `encode`, `decode`, `stats`. |
| MCP server adapter | Done | TypeScript MCP server (`bcp-mcp-server`) exposing read, inspect, and encode tools over stdio and HTTP transports. |
| TypeScript bindings (bcp-ts) | Planned | Targeting Bun runtime. Will provide encode/decode/render APIs for TypeScript/JavaScript consumers. |
| VS Code extension | Planned | Visual inspector for `.bcp` payloads. Block-level view with syntax-highlighted content, metadata overlays, and size statistics. |

---

## Phase 3: Ecosystem and Native Path

Phase 3 targets ecosystem adoption and the long-term vision of native binary ingestion by models.

| Deliverable | Status | Details |
|-------------|--------|---------|
| BCP as MCP content-type | Planned | Propose BCP as an optional content-type in the MCP specification, enabling native BCP transport in MCP tool responses. |
| Native ingestion experiments | Research | Collaborate with model providers on training binary token vocabularies that consume BCP blocks directly, eliminating the text decode step. |
| Shared compression dictionaries | Planned | Pre-trained Zstd dictionaries optimized for common programming languages (Rust, TypeScript, Python, Go). |
| Caching infrastructure | Planned | Content-addressed block store for caching and deduplicating BCP payloads across sessions and tools. |
