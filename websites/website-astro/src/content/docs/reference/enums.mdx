---
title: "Shared Enums"
description: "Wire-level reference for all 8 shared enumerations in the Bit Context Protocol: Lang, Role, Status, Priority, FormatHint, DataFormat, AnnotationKind, and MediaType."
---

All enumerations in the BCP protocol use single-byte wire encoding for compactness -- no strings, no multi-byte tags. A `Role::User` is 1 byte on the wire, not 4+ bytes for the string `"user"`.

Most enums are generated by a `wire_enum!` macro that produces `to_wire_byte()` and `from_wire_byte()` methods. `from_wire_byte` returns `Err(TypeError::InvalidEnumValue)` for unrecognized bytes, except for `Lang` which uses an `Other(u8)` variant for forward compatibility.

## Lang

Programming language identifier for CODE blocks. `Lang` is the one enum that does **not** use the `wire_enum!` macro -- it has a special `Other(u8)` variant that preserves unrecognized language IDs rather than erroring.

| Wire Byte | Variant | Wire Byte | Variant |
|-----------|---------|-----------|---------|
| `0x01` | Rust | `0x0A` | Shell |
| `0x02` | TypeScript | `0x0B` | SQL |
| `0x03` | JavaScript | `0x0C` | HTML |
| `0x04` | Python | `0x0D` | CSS |
| `0x05` | Go | `0x0E` | JSON |
| `0x06` | Java | `0x0F` | YAML |
| `0x07` | C | `0x10` | TOML |
| `0x08` | Cpp | `0x11` | Markdown |
| `0x09` | Ruby | `0xFF` | Unknown |

Any unrecognized byte value is stored as `Lang::Other(u8)`.

:::tip
New programming languages are added frequently, and a CODE block with an unknown language is still perfectly valid context. This is why `Lang` uses forward-compatible `Other(u8)` instead of erroring on unrecognized values.
:::

```rust
pub fn from_wire_byte(value: u8) -> Self {
    match value {
        0x01 => Self::Rust,
        // ... known languages ...
        other => Self::Other(other),
    }
}
```

## Role

Conversation turn role identifier.

| Wire Byte | Variant |
|-----------|---------|
| `0x01` | System |
| `0x02` | User |
| `0x03` | Assistant |
| `0x04` | Tool |

:::caution
An unknown conversation role would be semantically broken (the model cannot determine how to interpret the turn). Unlike `Lang`, `Role` returns an error for unrecognized wire bytes.
:::

## Priority

Block importance level for the token budget engine. Implements `PartialOrd` + `Ord` for comparison.

| Wire Byte | Variant | Budget Behavior |
|-----------|---------|-----------------|
| `0x01` | Critical | Always full content, even over budget |
| `0x02` | High | Full -> Summary -> Full (forced) |
| `0x03` | Normal | Full -> Summary -> Placeholder |
| `0x04` | Low | Summary -> Placeholder |
| `0x05` | Background | Placeholder -> Omit |

```rust
assert!(Priority::Critical < Priority::High);
assert!(Priority::High < Priority::Normal);
```

:::note
This ordering is used by the token budget engine to rank blocks during the two-pass decode: Critical blocks always get full content, Background blocks get a one-line reference, and everything in between is allocated proportionally.
:::

## Wire Encoding Pattern

All enums follow the same encoding pattern via the `wire_enum!` macro:

```rust
wire_enum! {
    #[derive(Clone, Copy, Debug, PartialEq, Eq)]
    pub enum Role {
        System = 0x01,
        User = 0x02,
        Assistant = 0x03,
        Tool = 0x04,
    }
}
```

The macro generates:

- `to_wire_byte(&self) -> u8` -- convert variant to its wire byte
- `from_wire_byte(value: u8) -> Result<Self, TypeError>` -- parse wire byte, error on unknown values

:::note[Info]
`Lang` is manually implemented (not macro-generated) because it needs the `Other(u8)` fallback variant for forward compatibility. All other enums use the macro and reject unknown wire bytes.
:::
